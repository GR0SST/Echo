# Deleted-profile storage (2026-10-26)

Arc's Settings → Profiles confirmation is 450 × 350 with an empty exact-name field, Cancel and a disabled Delete button. The installed reference still shows this single-profile sheet when Option-clicking minus. Querying “delete unused profiles”, right-clicking a row and attempting multiple selection did not expose the bundled bulk-deletion sheet. No profile was renamed, reassigned or deleted in Arc. The bundled bulk copy alone is not permission to invent a control.

Echo's existing individual sheet deletes only a named, unused, non-Default profile. Both individual deletion and the existing atomic captured-inventory model operation now retain explicit retired identities in session JSON. Historical archive provenance is retained. Default/live identities and invalid retirement watermarks are rejected on restore. IDs are never reused; missing directories are never treated as proof of deletion.

Only retirements captured when the canonical normal session is loaded are candidates for storage cleanup. Unsaved deletions in a live window cannot reclaim storage. After CEF initializes and owns its root, its persistent context registry refuses any store opened in that process; those stores wait for restart. A never-opened retired store is renamed to the separate `.retired-profile-<key>` namespace. Recursive cache/private capture removal and encrypted-vault/key cleanup then run on a background worker, so cache size does not stall the UI. Missing files are idempotent; aliases, Default and a conflicting original/quarantine pair are retained. Failed or interrupted cleanup retries on a later launch. No-engine/private/Blank windows cannot clear a vault through this path. Browser-owned `Captures/profile-<id>` directories use the same explicit retirement scope and refuse aliases; user Downloads/Desktop/Documents are never swept. The previous macOS compatibility service is reclaimed by exact root and profile ownership, enumerating attributes without reading password data. Current vault keys also use an attribute-only macOS delete; keychain access/ownership errors retain the retirement request for retry.

Regression coverage uses temporary fixture roots and an in-memory credential store: loaded-context refusal, restart quarantine, Default/other-profile preservation, symlink refusal, durable explicit identity retirement and vault/key destruction. GPUI covers the existing exact-name confirmation plus exclusion of unsaved live retirement from startup cleanup.
