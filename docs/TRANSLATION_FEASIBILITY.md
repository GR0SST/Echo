# Translation feasibility (2026-10-26)

Read-only inspection of the installed Arc 1.170 `ArcCore.framework/Versions/A/ArcCore` finds Chromium's translation-script endpoint `https://translate.googleapis.com/translate_a/element.js`, translation origin `https://translate.googleapis.com/`, and the Google translation WebUI CSP origins. The page context-menu reference exposes Chromium's “Translate to English” action. No translation of the owner's pages or request to this endpoint was performed.

Chromium's [Translate design](https://www.chromium.org/developers/design-documents/translate/) describes fetching the translation script from Google and sending page text to the Google translation service. The bundled endpoints match that architecture; there is no evidence here of an Arc-provided offline translation engine. Static endpoint inspection does not prove which network calls every language/build makes.

**Scope decision:** at the orchestrator's explicit instruction, reproducing the bundled Google-server translation service is out of scope under Echo's local-only/provider rules. Do not silently reuse Google's browser service or another product's credentials. A future user-supplied translation provider (or a separately qualified local engine) could support translation, language selection, original restoration and per-site policy. No such provider is supplied for this task. Existing local translation-preference reset remains available; it does not translate pages. Translation and its success/error toasts are excluded together, rather than reported as functional release gaps.
