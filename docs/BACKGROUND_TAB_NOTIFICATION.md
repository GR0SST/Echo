# Background-tab notification acceptance

The release inventory incorrectly called the hidden-sidebar notification missing. Both Command Bar Command-Enter and renderer background-open events already call `show_background_tab`, which retains the current selection and captures the new tab and local profile in the toast action. The action rejects removed or reassigned targets. This change corrects the inventory rather than adding a second notification path.

The source for the exact message `New Tab Created in %@` is Arc 1.170.0's extracted ToastController string group (line 47717 in the original reference extraction); see [the existing toast reference](TOAST_REFERENCE.md#round-3-existing-action-hooks). The regular toast presentation reuses the previously qualified toast shell. Background Space creation is a separate unfinished feature.

Fresh native acceptance uses `target/parity/background-tab/check-native.py`, a disposable session, a local HTTP fixture and real NSEvents. After hiding the sidebar, Command-Enter creates a background target while the source remains selected. Clicking the visible toast selects and loads the target. The first run observed exactly one request per document and a zero-status native quit. Two repeated separate-GPU runs and an in-process-GPU run pass the UI steps but reach CEF’s teardown watchdog after `ShuttingDown`; the latter writes `echo-dirty-shutdown.json` and terminates its network helper. The clean-quit integration gate is therefore still open, and this row is not marked done. Preserved failure logs: `target/parity/background-tab/separate-gpu-watchdog.log` `separate-gpu-watchdog-drive.log`, `in-process-watchdog.log`, and `in-process-watchdog-drive.log`. Execution traces are in `target/parity/background-tab/native/`. Repeat screenshots used stale marker files and are not accepted parity evidence; the retained local helper now clears both phase markers before a future rerun. This check does not qualify new pixel or motion parity.

Existing GPUI user-flow coverage: `background_command_bar_keeps_the_page_and_toast_reveals_the_created_tab` and `background_engine_request_keeps_focus_and_uses_the_hidden_sidebar_feedback` in `crates/browser/src/tests.rs`. No implementation change or redundant regression test is needed for the verified existing behavior.
